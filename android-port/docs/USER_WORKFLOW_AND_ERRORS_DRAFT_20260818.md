# 用户流程与错误文案草案(2026-08-18,N2-R1 修正版)

> 本文档是**未来 UI 的文字与状态设计草案**,不是任何已实现的功能,也不控制任何设备。
> 所有离线检查的输出都声明 `device_access=0`——这**只表示该步骤没有接触设备**,
> 绝不等于任何实机结论,也不构成 replay 成功或 LIVE PASS。
> 文中所有流程均要求**用户明确确认**后才能进入下一步;没有任何“一键绕过确认”的设计。
> 本修正版如实描述当前已知的录制/写入/清理边界:录制可能写入 fixed delta,
> 准备阶段可能有经过授权的基础设施操作,工具清理成功不等于游戏世界状态回滚。

## 1. 用户流程总览(未来 UI 设计)

```text
[放入录像/报告] → [离线校验] →(有效)→ [准备新进程:等待用户确认]
                                  ↘(无效)→ 显示问题,不进入任何下一步
[准备新进程] → [等待进入比赛] → [等待自然运行] → [录制]
    [录制 = 零输入模式 / 用户动作模式 / fixed-delta 模式,按已授权计划切换]
→ [需要手动 Retry] → [回放已就绪] → [回放执行中] → [严格验证] →(通过)→ [成功]
                                                          ↘(任一安全检查不过)→ [安全拒绝]
任何时候:进程变化 / 被其它工具跟踪 / 哈希不符 / 报告已存在 / 游戏崩溃 / 用户取消
→ 立即停止并进入对应状态,绝不自动重试;清理状态按报告判定,不默认宣称已回滚。
```

## 2. “现在需要我做什么”速查

| 场景 | 用户要做什么 |
|---|---|
| 校验录像/报告 | 把文件放入指定位置,然后点击“开始校验” |
| 准备新进程 | 阅读确认说明,明确点击“我确认,开始准备” |
| 等待进入比赛 | 正常进入一场比赛,不要暂停 |
| 等待自然运行 | 让比赛自然运行,不进行任何输入 |
| 零输入录制 | 完全不操作 |
| 用户动作录制 | 只执行当前屏幕提示的动作(如转向、刹车/漂移、氮气) |
| 需要手动 Retry | 按游戏的“重试”按钮(仅此一次,系统不会自动重试) |
| 回放已就绪 | 确认场地和车辆状态,点击“开始回放” |
| 回放执行中 | 不要操作;等待系统提示 |
| 出现任何错误提示 | 停止操作,按提示操作,保留报告和日志,不要反复重试 |
| 游戏崩溃/退出 | 先保存证据并确认旧进程已退出,再按“恢复建议”操作 |

## 3. 状态与错误文案

每个状态提供:状态 ID、用户看到的中文标题、说明、系统是否进行过写入(以及清理状态,
见“清理状态说明”)、用户下一步、安全/保留证据行为。

### 清理状态说明

工具清理(清理/回滚 hook、线程、临时基础设施)与游戏世界状态恢复是两件不同的事。
本草案使用四个清理状态词,由严格报告判定,UI 不得默认填写:

- `CLEANUP_NOT_NEEDED`:在任何 attach/hook/临时写入之前停止,不需要清理;
- `CLEANUP_CONFIRMED`:严格报告证明 hook/临时基础设施已恢复、线程已 detach、计数满足要求;
- `CLEANUP_ATTEMPTED`:已执行清理尝试,但缺少完整确认;
- `CLEANUP_UNKNOWN`:游戏崩溃、进程消失、通信中断或报告不完整,无法证明清理完成。

**工具清理不等于游戏世界状态回滚**:即使工具清理成功,也不能承诺车辆位置、速度、比赛时间
或其它游戏世界状态回到回放前。除非未来存在独立、严格验证的状态还原机制,否则不得使用
“世界状态已回滚”一类表述。

### 状态:OFFLINE_VALIDATING

- 中文标题:正在离线校验
- 说明:系统正在只读检查录像/报告的结构、版本、帧数、时间顺序和数值是否有限。此步骤不接触设备。
- 系统写入:无
- 用户下一步:等待校验完成,不要关闭窗口。
- 安全/保留证据行为:只读打开文件,绝不修改或删除原文件;校验期间不创建任何文件。

### 状态:OFFLINE_INVALID

- 中文标题:录像/报告无效
- 说明:文件结构、版本或内容不符合要求,可能是旧版本、被截断、被修改或不是本工具生成的文件。
- 系统写入:无
- 用户下一步:检查文件来源;必要时重新生成或重新导出;不要尝试“修复”文件。
- 安全/保留证据行为:保留原文件与任何相关日志;不自动删除、不自动覆盖;把原文件路径和错误提示记录下来。

### 状态:PREPARE_CONFIRMATION_REQUIRED

- 中文标题:需要你确认准备新进程
- 说明:下一步会停止当前游戏进程并准备一个新进程,这是不可逆的准备动作,必须由你明确同意。
- 系统写入:未开始(确认前不做任何准备)
- 用户下一步:阅读说明后明确点击“我确认,开始准备”;点击“取消”则停止,不进入下一步。
- 安全/保留证据行为:在确认前不改变任何游戏状态;取消时保留全部现有报告与日志。

### 状态:PREPARING_NEW_PROCESS

- 中文标题:正在准备新进程
- 说明:系统正在准备一个新的游戏进程。此阶段**尚未开始正式回放/动作/车辆物理写入**,
  但可能进行经过授权的基础设施准备操作:新进程生命周期操作、进程身份/start-time 校验、
  bootstrap、加载或映射只用于基础设施的 payload、临时进程内基础设施写入、验证后恢复/脱离。
  准备阶段“没有开始正式回放”不等于“准备阶段完全不触碰进程”,本草案不承诺准备阶段进程内零操作。
- 系统写入:尚未开始 gameplay replay/action/vehicle-physics writes;可能进行经过授权的基础设施准备操作
- 用户下一步:等待;不要手动启动或关闭游戏。
- 安全/保留证据行为:具体调用、写入、恢复、detach 计数必须记录在准备收据;任一哈希、
  PID/start-time、TracerPid 或准备后验证不符时 fail closed,保留收据与日志。

### 状态:WAITING_FOR_RACE

- 中文标题:等待进入比赛
- 说明:系统已就绪,等待你进入一场比赛。
- 系统写入:无
- 用户下一步:正常进入比赛(大厅、选车、开始比赛),不要暂停。
- 安全/保留证据行为:等待期间不做任何自动操作;超时或取消都保留现状与日志。

### 状态:WAITING_FOR_NATURAL_RUN

- 中文标题:比赛需要自然运行
- 说明:比赛必须自然运行,不能由系统或你进行任何输入,否则录制结果无效。
- 系统写入:无
- 用户下一步:不要按方向键、氮气、刹车,不要做任何触摸输入,让比赛自然进行。
- 安全/保留证据行为:若检测到输入或异常,停止并保留已录制内容与日志。

### 状态:RECORDING

- 中文标题:正在录制
- 说明:录制阶段的通用入口。具体写入语义由当前录制模式决定(零输入、用户动作或
  fixed-delta),本阶段是否写入游戏内存取决于模式与已授权计划;UI 必须显示当前模式与写入预算,
  不得默认宣称“完全只读”。
- 系统写入:视当前录制模式而定(见各录制模式状态;绝不默认宣称“只读”)
- 用户下一步:按当前录制模式的屏幕提示操作(见对应模式)。
- 安全/保留证据行为:录制文件与事件日志持续保存;停止或失败时不删除已写内容;
  每类写入(delta/control/physics)分开计数并保留。

### 状态:RECORDING_ZERO_INPUT

- 中文标题:零输入录制(anchor/预热/搜索)
- 说明:用于零输入 anchor、warmup 或 search 阶段。用户不得输入;只有当前阶段的严格计划
  明确规定时,才能显示 `gameplay_writes=0`。命中 trigger 后是否进入 fixed-delta 录制必须另行提示。
- 系统写入:观察/搜索阶段按计划可能保持零 gameplay write;命中 trigger 后按计划可能开始
  fixed-delta 写入(另行提示,不预先承诺)
- 用户下一步:完全不操作。
- 安全/保留证据行为:写入预算与计数器保留在报告;任何超出计划预算的情况立即 fail closed
  并保留报告与日志,不自动重试。

### 状态:RECORDING_USER_ACTION

- 中文标题:用户动作录制
- 说明:捕获用户真实转向、刹车/漂移、氮气或其它明确动作。用户必须按屏幕提示执行动作;
  提示必须说明动作名称、开始条件、持续时间/结束条件。动作录制不是键盘宏、画面识别或输入估算。
- 系统写入:按计划可能包含 fixed-delta 写入;control/physics 写入预算以已授权计划为准
- 用户下一步:只执行当前提示的动作(steering、brake/drift、nitro 等),不做提示之外的任何操作。
- 安全/保留证据行为:用户误输入或动作时机不符时停止当前录制并保留报告,不自动重试。

### 状态:RECORDING_FIXED_DELTA

- 中文标题:fixed-delta 录制
- 说明:当前录制可能逐帧写入 fixed delta。本次允许的最大帧数/最大写入次数来自已授权计划;
  必须分开报告 delta writes、control writes、physics/final writes。如果当前录制只允许
  fixed-delta,control/physics 写入必须保持 0,任何超预算立即 fail closed。
- 系统写入:逐帧 fixed-delta 写入(游戏内存写入);control/physics 按计划保持 0 或受限
- 用户下一步:按所在录制模式(零输入或用户动作)操作,等待完成。
- 安全/保留证据行为:三类写入分开计数并保留在报告中;超预算立即停止,保留报告与日志。

### 状态:RETRY_REQUIRED

- 中文标题:需要你手动重试
- 说明:为了对齐原版语义,需要你按一次游戏内的“重试”按钮。系统不会自动重试。
- 系统写入:无
- 用户下一步:按一次“重试”按钮,然后回到自然运行状态。
- 安全/保留证据行为:重试前后保留全部录制与报告;不自动重复此步骤。

### 状态:REPLAY_READY

- 中文标题:回放已准备,尚未开始正式写入
- 说明:回放内容已准备完成,但正式逐帧 replay/action/physics writes 尚未开始。
  此前可能已经发生新进程准备、基础设施加载、只读观察或经过授权的临时准备操作;
  因此只能说“正式回放写入尚未开始”,不能宣称整个游戏在此之前从未被改动。
- 系统写入:未开始正式回放写入(此前的基础设施/准备操作不计入回放写入)
- 用户下一步:确认场地与车辆状态后,点击“开始回放”。
- 安全/保留证据行为:未开始正式回放前可安全取消;用户取消后不得开始正式回放,
  但仍应执行或验证必要的工具清理,清理状态按报告判定。

### 状态:REPLAYING

- 中文标题:回放执行中
- 说明:系统正在按已录制的逐帧内容执行回放。此阶段会向游戏写入回放数据:
  逐帧 fixed-delta、已授权动作(control)写入与 final 64+12 correction(按计划)。
- 系统写入:正在写入(正式回放写入,仅本回放声明的字段)
- 用户下一步:不要操作,等待完成;任何异常不要强制重启后再来一次。
- 安全/保留证据行为:每一帧写入都有记录;失败时按报告判定清理状态
  (CONFIRMED/ATTEMPTED/UNKNOWN),保留报告、日志与原始录像,不承诺世界状态回滚。

### 状态:SUCCESS

- 中文标题:本次严格验证成功
- 说明:本次回放通过了全部严格检查(结构、哈希、进程身份、写入计数与结束报告)。
  只表示这一次成功,不代表完整比赛确定性,也不代表游戏世界状态被还原。
- 系统写入:已完成(正式回放写入已结束)
- 用户下一步:可以保存报告;如需再次运行,重新按流程确认。
- 清理状态:仅当严格结束报告证明时显示 `CLEANUP_CONFIRMED`;成功不代表游戏世界状态回滚。
- 安全/保留证据行为:报告与日志完整保留;不自动覆盖同路径已有报告;不自动开始下一次。

### 状态:FAIL_CLOSED

- 中文标题:已安全拒绝,未继续危险步骤
- 说明:某一项安全检查未通过,系统在继续更危险的步骤之前停止。
- 系统写入:已停止(不继续危险步骤)
- 清理状态:写入前失败可为 `CLEANUP_NOT_NEEDED`;写入后失败根据报告显示
  `CLEANUP_CONFIRMED`/`CLEANUP_ATTEMPTED`/`CLEANUP_UNKNOWN`;不得无条件宣称回滚已经完成。
- 用户下一步:按提示查看失败原因;不要直接重试同一操作,先解决问题。
- 安全/保留证据行为:保留报告、日志与原始文件;不自动删除、不自动重试写入。

### 状态:PROCESS_CHANGED

- 中文标题:游戏进程已变化
- 说明:系统检测到游戏进程标识或启动时间与开始时不同,说明进程已被重启或替换。继续操作不安全。
- 系统写入:已停止(不进行新写入)
- 清理状态:旧进程的清理状态可能为 `CLEANUP_UNKNOWN`;不得只写“不进行新写入”后假定已经恢复。
- 用户下一步:确认是否手动重启过游戏;按流程重新准备,不要跳过确认。
- 安全/保留证据行为:保留旧收据、报告与日志;不自动清除,不自动重启游戏。

### 状态:TRACERPID_NONZERO

- 中文标题:游戏正被其它工具跟踪
- 说明:系统检测到 TracerPid 非零,即游戏进程正被另一个调试或跟踪工具附加。继续操作可能互相干扰,必须停止。(技术含义见第 8 节详细信息。)
- 系统写入:已停止(不进行新写入)
- 清理状态:若在 attach/write 前检测,明确为 `CLEANUP_NOT_NEEDED`;若检测时点不确定,写“等待报告判定”。
- 用户下一步:关闭其它调试/跟踪工具后,重新按流程开始。
- 安全/保留证据行为:保留报告与日志;不自动关闭其它工具,不自动重试。

### 状态:HASH_MISMATCH

- 中文标题:文件哈希不一致
- 说明:本地、远端或证据文件的校验值不一致,说明文件可能被修改、损坏或来源不符。
- 系统写入:已停止(不进行新写入)
- 清理状态:若在 attach/write 前检测,明确为 `CLEANUP_NOT_NEEDED`;若检测时点不确定,写“等待报告判定”。
- 用户下一步:核对文件来源与版本;不要使用被修改的文件继续。
- 安全/保留证据行为:保留全部文件与哈希记录;不自动修复、不自动删除、不覆盖。

### 状态:REPORT_EXISTS

- 中文标题:目标报告已存在
- 说明:目标位置已经有一份报告。系统不会自动覆盖已有报告。
- 系统写入:已停止(未写入新报告)
- 清理状态:若在 attach/write 前检测,明确为 `CLEANUP_NOT_NEEDED`;若检测时点不确定,写“等待报告判定”。
- 用户下一步:选择新的报告位置,或确认后再决定;系统不会替你删除旧报告。
- 安全/保留证据行为:旧报告原样保留;不自动覆盖、不自动改名、不自动删除。

### 状态:GAME_CRASHED

- 中文标题:游戏进程已崩溃或退出
- 说明:游戏进程崩溃或退出,当前流程无法继续。工具层可能已执行恢复尝试,但这不能证明
  崩溃前已经发生的动作已被撤销。
- 系统写入:已停止(不再向已经退出的进程继续写入)
- 清理状态:默认 `CLEANUP_UNKNOWN`;只能保证不会再向已经退出的进程继续写入,
  不得声称崩溃前动作已回滚。
- 用户下一步:先保存证据并确认旧进程已经退出,再按“恢复建议”处理(见第 5 节)。
- 安全/保留证据行为:保留崩溃前的报告、日志、录像与系统生成的崩溃信息;不自动删除。

### 状态:USER_ABORTED

- 中文标题:已按你的要求取消
- 说明:你取消了当前操作,系统已停止,不会继续下一阶段。
- 系统写入:已停止(不继续下一阶段)
- 清理状态:若取消发生在正式写入前,可为 `CLEANUP_NOT_NEEDED` 或等待基础设施清理确认;
  若取消发生在写入后,必须等待报告判定,不得无条件宣称回滚已经完成。
- 用户下一步:确认保存或放弃当前内容;需要时重新开始。
- 安全/保留证据行为:保留取消前已生成的内容与日志;不自动删除。

### 状态:RECOVERY_TO_LOBBY

- 中文标题:建议回到大厅并保留现有报告
- 说明:建议先回到游戏大厅,并保留现有报告与录像,避免状态混乱造成误判。
  回到大厅是用户操作建议,不是系统保证。
- 系统写入:无(仅建议)
- 用户下一步:回到大厅;在确认场地/车辆状态后再考虑是否继续。
- 安全/保留证据行为:现有报告与录像全部保留;不自动继续任何流程。

## 4. 写入阶段与风险提示

| 阶段 | 是否写入游戏 | 风险等级 | 提示 |
|---|---|---|---|
| 离线校验 | 否 | 无 | 只读;`device_access=0` 仅表示未接触设备 |
| 准备新进程 | 尚未开始正式回放/动作/车辆物理写入;可能有授权的基础设施准备操作 | 低-中 | 不承诺零进程内写入;计数写入准备收据 |
| 等待/自然运行 | 否 | 无 | 禁止任何输入 |
| 录制(零输入模式) | 观察/搜索阶段按计划可能保持零 gameplay write;trigger 后另行提示 | 低 | 用户完全不操作 |
| 录制(用户动作模式) | 按计划可能包含 fixed-delta 写入 | 低-中 | 只执行提示的动作 |
| 录制(fixed-delta 模式) | 逐帧 fixed-delta 写入 | 中 | delta/control/physics 分开计数,超预算 fail closed |
| 回放已就绪 | 正式回放写入尚未开始 | 无 | 不宣称整个游戏从未被改动 |
| 回放执行中 | 是(正式回放写入:delta/control/final 按计划) | 中-高 | 每帧有记录 |
| 成功/失败收尾 | 正式写入已结束/已停止 | — | 清理状态按报告判定,不承诺世界状态回滚 |

- “尚未写入”“已经开始写入”“已停止”在 UI 上必须明确区分,文案不得混用。
- 任何阶段检测到进程变化、被跟踪、哈希不符、报告已存在或游戏崩溃,一律 fail closed。
- 本工具**不承诺任何“绝不崩溃”式的稳定性保证**——回放涉及游戏自身执行,任何文案不得出现此类承诺。

## 5. 崩溃、卡顿、比赛结束、误操作后的恢复建议

1. **游戏崩溃/退出**:先保存崩溃前的报告、日志、录像,并确认旧进程已经完全退出 →
   回到大厅(这是用户操作建议,不是系统保证)→ 重新开始必须再次经过完整确认与新进程身份检查;
   不保证相同操作下一次一定成功;不要直接“再来一次”。
2. **卡顿/无响应**:先等待系统超时;若超时提示失败,保留日志,不要强制结束游戏后立即重试;
   不能只凭画面判断清理完成,清理状态以报告为准。
3. **比赛结束/被撞毁**:录制内容可能不满足“自然运行/严格验证”要求 → 把录像标记为
   “不适用于当前严格验证”(不自动删除)→ 回到大厅 → 需要时重新录制。
4. **误按了输入**:零输入阶段一旦检测到输入,录制作废 → 停止并保留日志 → 重新开始录制。
5. **误点取消**:按 `USER_ABORTED` 处理;已生成内容保留,清理状态按取消时点与报告判定。

## 6. 报告与录像保留策略

- 报告、录像、日志与哈希记录在错误发生时**优先保留,不自动删除**。
- 已有报告**绝不自动覆盖**:目标路径已存在时进入 `REPORT_EXISTS`。
- “不适用于当前严格验证”的录像仅作标记,不自动删除。
- 用户主动清理只能由用户在界面上明确操作;系统不提供任何自动清理开关。
- 技术细节(进程标识、寄存器、跟踪状态、哈希值)放入“详细信息”折叠区,不放在主提示里。

## 7. 明确不会自动执行的操作

- 不会自动重启、自动进入比赛、自动按 Retry、自动重复写入;
- 不会自动覆盖已有报告;
- 不会自动删除或清理任何报告、日志、录像;
- 不会自动绕过任何确认(没有“一键绕过确认”);
- 用户取消后不会继续下一阶段;
- 不会自动重试已失败的录制或回放;重新开始不保证成功;
- 不会建议重试已退役的 PT-NB0/PT-NB1 路线(该路线已永久退役);
- FC-1 相关工作只描述为 BUILD_ONLY/OFFLINE,文案中不得出现任何把 FC-1 写成实机通过的表述;
- 结构校验通过不会显示成“回放成功”——两者文案严格区分;
- 不会自动宣称清理/回滚已完成:清理状态一律按严格报告判定。

## 8. 技术详细信息折叠区建议

- 校验明细:版本号、帧数、首/末 tick、哈希值、错误码;
- 写入明细:delta writes、control writes、physics/final writes 分开列出;
- 清理明细:清理状态词与报告依据;
- 进程信息(如需展示):进程标识、启动时间、跟踪状态(TracerPid);
- 完整命令行与校验输出;
- 以上信息默认折叠,主界面只显示面向非技术用户的中文说明。

## 9. 术语与边界

- 面向非技术用户,主文案避免 PID、ptrace、ABI 等术语;确需展示时放入“详细信息”。
- 一次单帧 Gate 通过只是**该帧**的验证结果,文案不得写成完整比赛确定性。
- 离线/结构校验通过 ≠ replay 成功 ≠ LIVE PASS;成功文案只用于严格验证通过的本次回放。
- `device_access=0` 仅适用于离线检查的声明;一旦进入任何实机流程,该声明不再适用。
- 录制“零 control/physics write”不等于“零游戏内存写入”(fixed-delta 写入也是游戏内存写入);
- 准备阶段“没有开始正式回放”不等于“准备阶段零进程内写入”;
- 工具清理成功不等于游戏世界状态回滚;不得使用任何“世界状态已回滚”式表述。
